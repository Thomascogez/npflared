# Tokens

Tokens are the credentials used by npm clients (and by the API itself) to authenticate against your registry.
They are sent as a `Bearer` token in the `Authorization` header, which is what npm and pnpm do when `_authToken` is set in your `.npmrc`.

:::warning
Firestash only stores a SHA-256 hash of each token. The plaintext token is returned **once**, when it is created, and cannot be retrieved afterwards. Store it somewhere safe.
:::

## Generate a new token 
:::info
In order to generate a new token, you will need to be authenticated and having at least the `token:write` permission with value `*`.
:::

You will need to send a `POST` request to the `/-/npm/v1/tokens` endpoint with the following body:

```js
{
	"name": "My token",
	"scopes": [
		{
			"type": "package:read",
			"values": ["*"]
		},
		{
			"type": "package:write",
			"values": ["@my-scope/my-package", "my-cool-package"]
		}
	]
}
```

The response contains the token details along with its plaintext value, which starts with `fst_`:

```js
{
	"id": "my-token-id",
	"token": "fst_...", // Only returned here, store it safely
	"name": "My token",
	"scopes": [...],
	"createdAt": 1734173399000,
	"updatedAt": 1734173399000
}
```

You can send has many scopes as you want.

| Scope type | Description |
| --- | --- |
| `package:read` | Read access to a package |
| `package:write` | Write access to a package |
| `package:read+write` | Read and write access to a package |
| `token:read` | Read access to a token |
| `token:write` | Write access to a token |
| `token:read+write` | Read and write access to a token |

:::info
The `values` property is an array of strings. Use `*` to match every package (or every token), or list the exact package names (or token ids) the scope applies to.
:::

## Get all tokens

You can get all tokens by sending a `GET` request to the `/-/npm/v1/tokens` endpoint.

```bash
curl -X GET https://my-firestash.dev/-/npm/v1/tokens
```

Each entry contains the token `id`, `name`, `scopes` and timestamps. Neither the token nor its hash is ever returned.

## Get a token

You can get a token by sending a `GET` request to the `/-/npm/v1/tokens/token/:id` endpoint.

```bash
curl -X GET https://my-firestash.dev/-/npm/v1/tokens/token/my-token-id
```

:::info
The `:id` parameter is the `id` of the token you want to get, as returned when it was created or listed.
:::

## Revoke a token

You can revoke a token by sending a `DELETE` request to the `/-/npm/v1/tokens/token/:id` endpoint.

```bash
curl -X DELETE https://my-firestash.dev/-/npm/v1/tokens/token/my-token-id
```

:::info
The `:id` parameter is the `id` of the token you want to revoke. The token stops working immediately.
:::

## Migrating tokens created before hashing

Tokens created by Npflared, which Firestash is forked from, were stored in plaintext. After upgrading and running the migrations they keep working: each one is hashed, and its plaintext removed, the first time it is used.

To hash the remaining ones in one go, run the following from the `api` directory:

```bash
pnpm migrate-tokens:prod
```

Use `pnpm migrate-tokens:local` for a local development database.
