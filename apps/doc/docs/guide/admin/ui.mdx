# Admin UI

Firestash ships a small web interface for administrators, served by the registry worker at `/_/admin` and protected by [Cloudflare Access](./authentication).

## Packages
- A searchable, paginated table of every published package with its latest version, version count and last update.
- A package page with the description, dist-tags, a copyable install command, the list of published versions and, for the selected version, the rendered readme and the dependencies.

Readmes are rendered from Markdown and sanitised before they are displayed. Package management is read-only.

## Tokens
- The list of registry tokens with their names, scopes and creation dates. Secrets are never displayed.
- A form to create a token with any combination of scopes, using `*` for every package or an explicit list of package names.
- The generated token is shown exactly once, with a copy button.
- Revocation with a confirmation step.

## How it is served
The UI is a Svelte 5 single-page application (`apps/api/admin`) built with Vite, Tailwind CSS 4 and shadcn-svelte. It lives in the same Vite project as the worker through the [Cloudflare Vite plugin](https://developers.cloudflare.com/workers/vite-plugin/): `vite build` emits the worker and the client assets together, and the worker serves the assets itself with `run_worker_first`, so that every request to the admin area goes through admin authentication before anything is served. Only the hashed build assets under `/_/admin/assets/` are served directly. Deep links are answered with the application shell.

`pnpm deploy` in `apps/api` builds everything, applies the database migrations and deploys the worker with the generated configuration; see [Workers Builds](../install/workers-builds) for deploying from Git.

## Developing the UI
1. In `apps/api`, copy `.dev.vars.example` to `.dev.vars` (this selects the `local` admin authentication provider, which only trusts requests addressed to `localhost`) and apply the local migrations with `pnpm migrate:local`.
2. Start `pnpm dev` in `apps/api` and open `http://localhost:5173/_/admin/`. The worker runs in the Workers runtime inside the Vite dev server, so the registry, the admin API and the UI share one origin, with hot module replacement for both.

`pnpm preview` serves the production build the same way, which is the closest thing to a deployment without deploying.
