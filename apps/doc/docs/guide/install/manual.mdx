# Manual

:::tip
The recommended way to deploy is [Workers Builds](./workers-builds), which needs no local tooling and keeps the repository free of account-specific values. The steps below deploy from your machine instead.
:::

### 1. Clone the project
```shell
git clone https://github.com/colinbate/firestash.git
cd firestash
```

## 2. Install dependencies
Install the dependencies of the whole repository, then work from the `apps/api` directory for the remaining steps:
```shell
pnpm install
cd apps/api
```

:::info
This project uses `pnpm` as its package manager.
:::

## 3. Configure project
Copy `.env.example` to `.env.local` and fill in the values for your account: they are applied to the worker configuration when building, so `wrangler.toml` itself does not need to change. The sections below describe where each value comes from.

### Configure your R2 bucket
Go to your [Cloudflare Dashboard](https://dash.cloudflare.com/) and create a new **R2** bucket.
Copy the name of your bucket into your `.env.local` file 

```shell title=".env.local"
FIRESTASH_R2_BUCKET_NAME=BUCKET_NAME # Replace BUCKET_NAME with the value you have previously copied
```

### Configure your D1 database
Go to your [Cloudflare Dashboard](https://dash.cloudflare.com/) and create a new **D1** database.
Copy the id and the name of your d1 database


```shell title=".env.local"
FIRESTASH_D1_DATABASE_NAME=D1_DATABASE_NAME # Replace D1_DATABASE_NAME with the value you have previously copied
FIRESTASH_D1_DATABASE_ID=D1_DATABASE_ID # Replace D1_DATABASE_ID with the value you have previously copied
```

### Configure your domain and admin access
Set `FIRESTASH_CUSTOM_DOMAIN` to the domain of the registry, and `CF_ACCESS_TEAM_DOMAIN` and `CF_ACCESS_AUD` to the values of the Cloudflare Access application protecting `/_/admin` (see [Admin authentication](../admin/authentication)).
## 4. Deploy your firestash worker
Once everything is set-up you can build, run the database migrations and deploy your worker in one go.
<PackageManagerTabs command="run deploy" />

## 5. Create your first token
Open `https://<your domain>/_/admin`, sign in through Cloudflare Access and create a token from the **Tokens** page.

If you prefer not to use the admin UI, you can create an initial token with elevated privileges directly in the database instead.

Only a SHA-256 hash of the token is stored in the database, so generate a random token and its hash first:

```bash
ADMIN_TOKEN="fst_$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '=')"
ADMIN_TOKEN_HASH=$(printf '%s' "$ADMIN_TOKEN" | shasum -a 256 | cut -d ' ' -f 1)
echo "Your admin token: $ADMIN_TOKEN"
```

:::warning
Keep the printed token somewhere safe: it cannot be recovered from the database afterwards.
:::

Then insert its hash:
```bash
npx wrangler d1 execute DB --remote --yes --command "INSERT INTO token (id, token_hash, name, scopes) VALUES (lower(hex(randomblob(16))), '$ADMIN_TOKEN_HASH', 'admin-token', '[{\"type\": \"token:read+write\", \"values\": [\"*\"]}, {\"type\": \"user:read+write\", \"values\": [\"*\"]}, {\"type\": \"package:read+write\", \"values\": [\"*\"]}]')"
```

And we are done 🎉
